# Independent reviews


`/fusion review run-N` starts an independent review of a run that has ended: an `ask` child in review mode, which the run that made the change never briefed. It runs the `ask` role, with that role's read-only tools and `contracts/ask-review.md` appended to its system prompt. The review is an ordinary run, so it takes the next handle, records its own `pi-fusion` entry, always runs in the background and reports through the background message. Its prompt names the run it reviews, tells it that the change sits in the working tree as uncommitted edits, points it at `git status --porcelain`, `git diff` and the files themselves, lists the paths the run changed, and carries the run's original task and report, each capped at 32 KiB. The task, the report and the failure go in as quoted data, each between markers of its own that the quoted text cannot close, and the prompt says that they are another agent's text: an instruction inside them is a finding to report, never one to follow, and the review changes nothing in the tree whatever they ask. It also says that the tree can hold work the run did not do, so the reviewer judges the listed paths and calls the rest out instead of reviewing it.

Only an `implement` or `ultracode` run that has ended `done` or `failed` with at least one changed file can be reviewed. A review of a run that is still active, of an `ask` run, of a run that changed nothing, or of a run that was cancelled or aborted is refused with the reason, and so is a review while `PI_FUSION_BUDGET_LIMIT_USD` blocks new runs, or of a run an earlier Pi process made in another working directory. Reviewing the same run again starts another review; the run then points at the newest one. A run whose state has just turned `done` is still listing the files it changed, and `/fusion review` waits for that list rather than refusing the run as one that changed nothing.

The user sees `run-2 reviews run-1 in the background; its report arrives as a message`, and the host gets a followUp message that starts no turn. The links show on both runs: the review's line in `/fusion status` and `claude_control status` reads `run-2 · ask · opus · done · background · 12s · review of run-1`, its report arrives as `Background run run-2 (ask, review of run-1) done.`, the reviewed run's tool result and end notice end with `run-2 reviews this run in the background; its report arrives as a message.`, its card header adds `reviewed by run-2`, and the dashboard lists Reviews and Reviewed by among a run's facts.

With `PI_FUSION_AUTO_REVIEW=1` the extension starts the same review on its own when an `implement` or `ultracode` run the `claude` tool started ends `done` with changed files. It starts once per run, before the run's own report reaches the host, so the report and the tool result carry the review line. Only a run the `claude` tool started gets one, so a review never reviews a review, and a failed, aborted or cancelled run never gets one. If the review cannot start, because the budget limit blocks it or for any other reason, the user is told why and the run reports as usual.
